# ドキュメント規約

- 新しい機能、モジュール、公開データ型、またはクラス相当の構造を実装する場合は、実装前に設計ドキュメントを作成または更新してください。
- 新規設計ドキュメントには、少なくとも責務、公開インターフェース、依存関係、処理フローを記載してください。
- 設計ドキュメントは`docs/designs/<機能名またはモジュール名>.md`へ配置し、ファイル名は小文字kebab-caseを使用してください。
- 設計ドキュメントは[設計ドキュメントのテンプレート](design_document.md)を使用してください。
- 本文は日本語で記述してください。
- ソースコード上の識別子、パス、コマンドは英語表記を使用してください。
- 概念図、依存関係図、フロー図はMermaidで記述してください。
- ディレクトリツリーやコマンド例は、用途に応じて`text`または言語別のコードブロックを使用してください。
- 実装と仕様が変わった場合は、関連するドキュメントも同時に更新してください。
- 未決定事項と確定事項を明確に区別してください。
